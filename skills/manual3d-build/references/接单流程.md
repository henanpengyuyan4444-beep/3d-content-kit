# 从材料到成品：三条入口

同一套引擎，三种收料方式。按客户给的东西选入口，不用都走。

## 入口一：客户给手册（照片/PDF）——最常见

```bash
# 1. PDF 拆页（拍照的话跳过这步，直接命名 p01.png…）
python scripts/pdf2pages.py 手册.pdf pages

# 2. 生成骨架（零件占位 + 页映射）
python scripts/new_sku.py pages kehu-bookcase-80

# 3. 人工读手册，填尺寸与步骤（这一步是核心，见下面）
#    改 kehu-bookcase-80.json

# 4. 校验 + 生成
python scripts/check_sku.py kehu-bookcase-80.json
node scripts/build.mjs kehu-bookcase-80.json --out dist
```

读手册时按这个顺序，别跳：

1. **先看零件清单页**：有几块板、几颗什么螺丝，把零件名抄下来。
2. **再看步骤图**：每步装了哪些件、往哪个方向装。
3. **最后算坐标**：先定整机尺寸，再定侧板位置，最后让横板去贴合侧板内表面。
4. 每算完一块板，问自己：它和谁接触？接触面坐标对上了吗？

常见坑（每次都会遇到）：

- 同一块板在多个视角出现，被数成两三块。
- 层板画成左右两段，其实是整块（中间没有竖板时）。
- 尺寸看着像厘米，其实是毫米。
- 步骤顺序按"应该先装谁"写，而不是按手册。

## 入口二：客户填表（两张 CSV）——最快

```bash
python scripts/csv2sku.py 零件表.csv 步骤表.csv \
    --slug kehu-bookcase-80 --name "客户书柜" --size 800x2020x280 \
    [--pages 6,7,7,8,9] --out kehu.json
python scripts/check_sku.py kehu.json
node scripts/build.mjs kehu.json --out dist
```

`--pages` 是每一步对应的原页页码，可选；给了就出原页对照面板。

客户表填错是常态，`check_sku.py` 会把问题指出来（引用不存在、少板、尺寸超整机），把结论原样转给客户即可。

## 入口三：客户给数据/模型——最准

- 给 JSON：直接 `check_sku.py` → `build.mjs`。
- 给 glTF/STEP：先转 glTF，再给引擎加加载器（约 2 天），之后步骤照旧人编。

## 三条入口的共同出口

无论从哪进，出口都是同一个文件夹：

```
dist/<slug>/index.html   双击可看
```

以及同目录的 `data/sku.js`（改文案改这里）和 `manual-pages/`（原页图）。

## 什么时候必须人工介入

- 手册缺步骤图 → 只能按常见装法推断，交付时标"推断"。
- 零件名不统一（一会儿"侧板"一会儿"旁板"）→ 统一命名后再进表。
- 有复杂机构（滑轨、气撑、玻璃门）→ 五金会简化，先跟客户说清。
