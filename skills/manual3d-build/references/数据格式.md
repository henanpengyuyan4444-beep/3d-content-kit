# 数据格式

一份 SKU 就是一个 JSON。字段与项目里的 `custom` 规格一一对应，可以直接喂给引擎。

```json
{
  "slug": "kehu-bookcase-80",
  "brand": "客户品牌",
  "name": "两门书柜",
  "size": { "w": 800, "h": 2020, "d": 280 },
  "minutes": 45,
  "people": 1,
  "difficulty": 2,
  "parts": [
    { "id": "A", "name": "左侧板", "size": [18, 2020, 280], "pos": [-391, 1010, 0], "material": "board" },
    { "id": "B", "name": "右侧板", "size": [18, 2020, 280], "pos": [391, 1010, 0], "material": "board" },
    { "id": "C", "name": "顶板", "size": [764, 18, 280], "pos": [0, 2011, 0], "material": "board" },
    { "id": "D", "name": "底板", "size": [764, 18, 280], "pos": [0, 75, 0], "material": "board" },
    { "id": "E", "name": "层板", "size": [764, 18, 262], "pos": [0, 980, 0], "material": "board" },
    { "id": "F", "name": "背板", "size": [800, 2020, 3.5], "pos": [0, 1010, -138], "material": "fiber" }
  ],
  "steps": [
    {
      "title": "把木榫敲进四块横板",
      "detail": "每块板四根，敲到底。",
      "add": [],
      "fix": [{ "kind": "dowel", "count": 16, "to": ["C", "D", "E"] }],
      "tools": ["hammer"],
      "pose": "+y"
    },
    { "title": "侧板扣到底板", "add": ["A", "B", "D"], "pose": "+y" }
  ],
  "stepPages": [
    { "page": 6, "src": "/manual-pages/kehu-bookcase-80/p06.png" },
    null
  ]
}
```

## 单位与坐标

- 全部毫米。写厘米是最常见的错误（整柜会变成 20 毫米高）。
- 原点在成品底面中心：`x` 左右（正面看），`y` 离地高度，`z` 从后往前（背面为负）。
- `size` 是**成品姿态**下的 `[宽, 高, 深]`；`pos` 是这块板的中心点。
- 相接的两块板必须面贴面：算完先核对相邻两块的内表面坐标是否相等。

## 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| slug | 是 | 小写加连字符，用来放页图目录 |
| name / brand | 是 | 手册上印的名字，看不到就留空字符串 |
| size | 是 | 整机外廓 `{w,h,d}`，毫米 |
| minutes / people / difficulty | 否 | 估算，用来显示"还要多久""需要几个人" |
| parts[].id | 是 | A、B、C…；删除零件后要重新编号 |
| parts[].size | 是 | `[宽,高,深]` |
| parts[].pos | 是 | 成品里的中心点 |
| parts[].material | 否 | board（刨花板/中纤板）、fiber（薄背板）、wood（实木）、metal、soft |
| steps[].title | 是 | 一句短指令，30 字以内 |
| steps[].detail | 否 | 一到两句解释 |
| steps[].add | 是 | 这一步接上去的零件 id，每块板只出现一次 |
| steps[].fix | 否 | `[{kind, count, to}]`，五金类型见下表 |
| steps[].tools | 否 | allen、screwdriver、flathead、hammer、drill、wrench、level、tape、pencil、knife |
| steps[].pose | 否 | `+y`、`-y`、`+x`、`-x`、`+z`、`-z`，表示这一步产品怎么放 |
| steps[].warnings | 否 | two、loose、hand、wall、square、floor、face、tip |
| stepPages[] | 是 | 与 steps 一一对应：`{page, src}` 或 null |

## 五金 kind

dowel（木榫）、camScrew（偏心螺丝）、cam（偏心轮）、screw、nail、pin（搁板托）、bolt、legScrew、hinge、knob、handle、bracket（墙固定件）、glide（毛毡垫）、plate（连接板）。

## 命名经验

- 同一块板在多个视角出现，只写一条。
- 中间没有竖板时，画成左右两半的层板是同一块；中间有竖板才是两列各自的层板。
- 名称里带"侧板/竖板/旁板/立板"的会被当成竖板；带"层板/搁板/隔板"且厚度小于 100mm 的会被当成层板。

## 多配置（同一款产品的不同尺寸/型号）

一份文件里放多个配置，构建时每个配置生成一个 3D 页面，并自动生成选择页：

```json
{
  "slug": "billy-multi",
  "name": "BILLY 书柜（两种宽度）",
  "configs": [
    { "id": "billy-80", "label": "80 厘米宽", "size": {...}, "parts": [...], "steps": [...] },
    { "id": "billy-40", "label": "40 厘米宽", "size": {...}, "parts": [...], "steps": [...] }
  ]
}
```

- 每个配置的写法和单配置完全一样（size / parts / steps / stepPages）。
- 构建产物：`dist/<slug>/index.html` 是选择页，`dist/<slug>/<配置id>/index.html` 是对应的 3D。
- 校验脚本也认多配置，逐个跑 G1 到 G5 并汇总。
